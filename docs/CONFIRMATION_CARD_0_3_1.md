# 提交前配置卡片

界面按已确认的 [效果图](../design/concepts/tripo-confirmation-card-v1.png) 实现：顶部输入视图、生成配置、贴图设置、更多配置、费用与操作按钮、底部倒计时。深浅主题跟随宿主，375 px 下无横向溢出。

Agent 的生成/编辑工具统一返回可编辑配置表单，不暴露 `submit` 或 `review`。卡片挂载并显示在可见页面后，才由 app-only `ready` 动作启动服务端 60 秒倒计时。后台创建记录、隐藏卡片和等待宿主渲染都不会开始计时。编辑暂停；保存验证配置、更新同一草稿与费用预估，校验通过后立即提交，不重启倒计时。确认/自动提交共用持久提交边界，始终使用表单最新保存的参数；取消不再提交。`tripo_submit_task` 和 `tripo_run_workflow` 仅供工作台内部使用，不暴露给 Agent。旧草稿卡片仍可查看配置，复用原 ID；旧输入若被截断则只显示冻结参数，不用不完整内容覆盖记录。

创建与状态查询回执说明自动提交流程，并返回 `next_action`。Agent 使用 `tripo_get_configuration_review` 的 `wait_ms:60000` 只读等待当前卡片：提交、取消、失败或用户开始编辑时提前返回；正常等待超时继续查询同一 ID。`pending`／尚无可见性回执不是“提交接口缺失”，不可据此代点界面、要求开放直接提交工具或重复创建任务。等待不触发可见性确认、倒计时或生成请求；最终提交状态以最新卡片回执为准。

卡片不显示原始文件路径。卡片展开后在后台预上传、审核输入图片，修改参数按账号和图片内容复用上传结果，不重复上传。预上传不发起生成请求；保存配置校验并更新费用后立即发起提交。提交前仅公开本地 `draft_id`；收到最终提交回执后才返回 `task_id`。智能体使用公开只读工具 `tripo_get_configuration_review` 按稳定 `review_id` 跟踪当前配置，提交后再按最终任务 ID 查询进度。输入缩略图通过 app-only `tripo_ui_review` 的 `preview` action 读取已验证的冻结快照；Studio 输入通过已有有界媒体读取。图像字节仅在工具结果 metadata 中。替换图片先暂停倒计时，使用现有本地导入工具，保存后才替换任务输入。结果继续使用图片/3D 预览，并刷新活动任务。

验证：90 项测试通过；标准 AppBridge 浏览器宿主验证了四视图、几何开关与参数映射、修改后费用从示例 40 更新为 55、取消、图片替换与持久输入保存、375 px 布局以及浅/深色主题。计费与远端提交在这个浏览器宿主中为隔离模拟，没有执行 Studio 付费生成。

实际渲染截图：`output/playwright/approved-card-dark.png`、`approved-card-light.png`、`approved-card-narrow.png`、`approved-card-requoted.png`。本机安装包已同步；重载插件连接后发现新的工具/资源。浏览器宿主验收不等于 Codex 原生聊天渲染验收。
