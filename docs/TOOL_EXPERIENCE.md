# 工具交互、Schema 与 Skill 设计

状态：设计契约，尚未接入真实 Studio；下述接口名为提案。2026-10-08。

## 三层职责

| 层 | 负责 | 不承担 |
| --- | --- | --- |
| Schema | 参数类型、单位、必填/默认值、互斥项、输出结构、错误结构 | 解释整套创作流程 |
| Tool 描述 | 何时使用、前置条件、副作用、异步行为、下一步 | 重复维护完整参数表 |
| Skill | 意图路由、能力发现、跨工具编排、失败恢复、产物交付 | 固定模型版本、猜测 ID、复制 schema |

三者都要做。以共用操作注册表生成独立 tools、Workflow 操作目录与参数文档。UI 的字段约束复用 schema，交互布局单独维护。动态能力查询决定当前账号、模型、部件可以使用哪些操作。

## 每项工具必须完成的交互闭环

1. 可发现：名称和描述能区分生成、编辑、查询、下载；明确是否产生新资产或修改已有资产。
2. 可准备：查询真实输入、模型能力、部件和动画预设；校验格式、单位及参数组合。缺失且影响结果的重要选择通过表单或简短追问补齐，其余应用明确默认值。
3. 可提交：显示目标资产、参数和提交数量；承接用户已有授权。仅在关键决策未明确时要求补充，不为每一个内部步骤重复确认。不能伪造费用。
4. 可跟踪：异步操作返回稳定任务 ID；工具和工作台读取同一记录。展示真实阶段；无百分比就只显示阶段。
5. 可恢复：登录失效暂停依赖操作，登录完成后先核对原提交；限流退避；未知提交结果不自动重提。
6. 可交付：返回资产 ID、格式、预览/下载入口、产物位置和下一步可用操作；生成成功与下载成功分别记录。

完整覆盖指每个操作都有上述闭环，不只是注册一个 tool。覆盖矩阵列：功能 / 独立 tool / 输入 / 输出 / 前置条件 / 费用属性 / UI 入口 / 失败恢复 / 实测证据。所有 15 个已发现 operation 与账号、查询、下载能力都要逐项验收。

## 建议任务与错误结构

任务：`task_id`、`operation`、`status`、`phase`、`input_asset_ids`、`output_asset_ids`、`created_at`、`updated_at`。状态提案为 queued / running / waiting_for_auth / succeeded / failed / canceled / outcome_unknown；适配旧 Workflow 状态时需要显式转换，不能直接改变现有服务契约。

结果：结构化 `structuredContent` 配合简短可读摘要。产物引用区分本地路径、可下载资源与短期远端 URL；错误结果使用 MCP 的 `isError`，并返回可处理的结构化细节。

错误：`code`、`message`、`retryable`、`submission_state`（not_submitted / submitted / unknown）、`next_action`、可选 `task_id`。参数校验与账号权限失败不可通过原样自动重试解决；只有明确未提交的请求才允许按策略重试。非幂等操作不能只凭 `retryable` 重发。

核心错误类别：AUTH_REQUIRED、INVALID_INPUT、UNSUPPORTED_CAPABILITY、INSUFFICIENT_CREDITS、RATE_LIMITED、REMOTE_FAILED、OUTCOME_UNKNOWN、DOWNLOAD_FAILED。

## 生成卡片与溯源数据契约

以下为设计字段，具体命名在实现时统一到共用 schema。卡片和工作台从后台读取同一记录，不能在前端另存一份任务真值。

| 记录 | 必要信息与语义 |
| --- | --- |
| 参数草稿 | 输入素材/提示词、目标资产、操作、模型版本、当前参数与数量；可编辑，尚未提交 |
| 提交快照 | 解析默认值后的实际参数、输入素材版本及角色（如正/背视图）、提示词、操作/schema/插件版本；提交时冻结 |
| 本地任务 | 稳定 `task_id`、账号作用域、操作、状态与阶段、快照引用、创建/提交/更新时间 |
| 远端关联 | Studio 返回的真实任务/项目/资产 ID；允许一个本地操作关联多个远端步骤；记录尚未返回或不可用的原因 |
| 来源关系 | 父任务 ID、输入资产及版本、输出资产及版本；支持多输入、分支、重试和重新生成的关联 |
| 产物与下载 | 格式、稳定资产引用、本地保存位置、下载状态、可获取时的内容校验值；不只保存短期下载 URL |
| 调用来源 | 对话调用或工作台操作、可获取时的 Codex 对话/工具调用引用；宿主未提供时留空并说明原因 |
| 事件历史 | 带时间的排队、提交、远端接受、阶段变化、失败、产物生成及下载事件；脱敏且可追加查询 |

原始输入应保留可追溯副本或稳定版本引用，可获取时记录内容校验值；只保存可被覆盖的文件路径不足以标识输入。输入被删除或不可访问时明确显示，不声称仍可复现。远端服务若返回实际采用的参数，另存为执行回执，不覆盖原提交快照；未披露的服务端默认值标注未知。

### 持久化与提交顺序

1. 提交前持久化本地任务、冻结快照和本地去重标识。
2. 写入提交意图后调用 Studio；若远端支持幂等键，则复用对应键，不能假设远端支持。
3. 收到回执后关联真实远端 ID，追加事件并更新状态。崩溃或响应丢失时保留原任务并标记待核实，不自动生成另一条提交。
4. 后台查询原任务，保存输出资产及来源边；下载单独记录状态。
5. 用户明确重新生成或重试生成时创建新任务，以关系字段关联原任务，保留旧快照、错误及产物。查询、恢复和重试下载不创建新的生成任务。

记录保存在插件本地持久存储中，按 Studio 账号隔离；普通状态查询、卡片重载、升级或重启不能删除或重建来源历史。Cookie、Token 和签名凭据不进入溯源字段或事件日志。

### 卡片展示规则

- 参数卡片：素材缩略图/文字输入、关键参数、完整参数展开区、提交数量和开始操作。明确区分可编辑草稿与已冻结参数。
- 任务卡片：固定本地任务 ID、操作名称、当前阶段、已知远端关联、失败下一步或输出入口。未获取真实百分比时只显示阶段。
- 结果卡片：预览、资产引用、下载状态、「查看来源」及继续处理入口。
- 来源详情：以处理链和逐步详情展示输入 → 任务 → 输出；每步能展开当时参数、时间、远端关联和错误事件。
- 与 Codex 的交互：左侧对话中的卡片可以打开右侧面板中的同一任务/资产；具体宿主跳转方式仍需实测。不复制聊天全文作为溯源依赖。

## Skill 编写提纲

最终插件需交付 `skills/tripo-studio/SKILL.md`，至少包含：

- 触发范围：Studio 素材、模型生成与编辑、资产管理、导出；明确使用 Studio 账号。
- 入门路径：查登录状态；需要登录时引导官方浏览器流程；登录后持久鉴权并以 headless 方式执行，用户可关闭浏览器；禁止把凭据放进对话，不得要求用户保持浏览器或 Studio 页面打开。
- 选择规则：单项操作使用独立 tool，多步创作使用同一操作层的 Workflow；先读取实时 schema 与能力。
- 输入绑定：使用实际返回的资产 ID、部件名和 preset；多候选优先展示缩略图供选择。
- 常见配方：单图 → 智能网格；模型 → 重拓扑 → PBR；模型 → 绑骨 → 动画。
- 长任务：保存真实任务 ID，查询原任务，不以超时为由重复创建。
- 溯源：所有生成和后处理绑定后台任务及冻结参数；继续处理引用真实输入资产版本，回答来源问题时读取持久记录，不凭聊天内容重构历史。
- 异常恢复：区分登录、额度、参数、限流、远端失败和提交状态未知。
- 交付：展示预览、产物与后续可做操作；如下载失败，保留已成功的远端任务结果。

正式 skill 在接口命名稳定后编写并以实际注册工具校验；本轮不制作包含虚构工具名的可执行 skill。

## 工作台交互验收

- 登录后关闭登录窗口、全部 Studio 标签页并退出可见浏览器，独立 tools、Workflow 和工作台仍可执行生成、查询、处理和下载；浏览器关闭时重启插件仍可复用有效会话与恢复任务。
- 工具调用和 UI 按钮使用相同能力与任务记录，不存在两套提交路径。
- 已有资产处理：选择资产 → 能力检查 → 参数 → 提交 → 状态 → 结果 → 下一项操作。
- 创建：输入方式选择 → 文件/文字 → 质量参数 → 提交 → 状态 → 预览与下载。
- 所有视图包括首次空状态、加载、成功、失败、登录失效与不支持状态。
- 错误提示明确已经提交与否、下一步操作，以及是否可能再次消耗额度。
