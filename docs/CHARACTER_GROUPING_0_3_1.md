# 角色资产分组 0.3.1

角色身份是分组维度：同一角色的参考图、多视图、模型、贴图、绑定、动作、导出归在一起。工具定义和 Skill 都要求 AI 从用户上下文选择简短一致的角色名。服务端不额外调用模型，也不按视觉相似度猜测身份。

28 个操作工具新增两个通用字段：

- `character_name`：1–80 字符的具体角色名；NFKC、空格和英文字母大小写归一化生成稳定组 ID，不把角色名发送给 Studio。
- `parent_task_id`：继续来源任务时明确传入。角色自动继承；显式角色名可覆盖。同名时沿用来源的组 ID。

没有显式父任务时，按已记录的项目、图片、动作 ID 或输出／下载路径继承。来源对应多个角色时保持未分组并返回提示。仅描述明确包含 `角色：名字` 或 `Character: Name` 时才作名称推断；普通描述与文件名不作为角色身份。不同远程账号的任务不相互继承；本地输出可通过实际来源任务衔接。

工作流支持顶层角色名与父任务 ID，后续步骤继承前一步；步骤输入中的角色名可覆盖。一个任务只有一个角色；包含不同角色的独立批量应拆成不同角色的任务或工作流。

任务持久记录与公共结果增加 `character_group:{id,name,assigned_by,source_task_id?}`。分组元数据独立于付费 payload、快照和 request_hash。相同付费输入仍去重；明确指定不同角色时返回 `TASK_GROUP_CONFLICT`，不创建重复收费任务。

新增工具：

- `tripo_list_task_groups`：跨全部保留任务统计角色、状态和处理中数量，可按状态过滤。沿用存储索引最多 5000 条的范围。
- `tripo_set_task_character`：修正一条任务的分组；传 null 移至未分组。保留已冻结请求、确认、状态和既有后续任务；修改会记入事件。继续修改后的来源时显式传 `parent_task_id`。

当前 UI 已改为直接多选和分组卡片，详见 [资产分组卡片](ASSET_GROUP_CARDS_2026-10-09.md)。以下为之前版本的角色筛选接口说明。`tripo_list_models` 和 `tripo_list_image_assets` 返回 `character_group`、可选角色列表 `character_groups`，并支持 `character_group_id`。筛选页的模型总数为 null，界面不把未筛选的远程总数当作筛选结果总数。

资产身份通过当前账号最多 5000 条保留任务的 remote/result 输出 ID 关联；支持批量模型和嵌套输出，最新输出记录优先，旧资产或没有角色记录的资产归入未分组。输入引用、描述或文件名不作为资产角色身份。任务中心按时间显示任务，并保留状态筛选、进度及参数详情。任务元数据与创建页角色输入继续作为资产归属和后续操作继承的来源。

总计 59 个工具（57 个模型可见工具、2 个 app-only 媒体工具），操作类型仍为 28。自动化测试覆盖分组持久化、父任务／来源继承、跨账号边界、混合来源、有限名称推断、去重冲突、修正不改变付费参数、旧记录兼容和分组分页。

本次验证：77 项测试全部通过；分发包 MCP 验证实际创建带角色的本地任务、列出组、修正角色、按组过滤。浏览器标准 AppBridge 宿主的隔离记录验证角色折叠／筛选、修正后计数刷新，以及文字创建草稿自动归入“柯莱”。付费分发在验收宿主中被禁用。420 px 面板的 `clientWidth` 和 `scrollWidth` 均为 420；长描述不会横向溢出。截图保存在 `.local/verification/character-groups-v3-1/`。原生 Codex 侧栏可见性不在此浏览器验收范围内。
