# Tripo Studio：DeepSeek Harness 与 Desktop 支持计划

日期：2026-11-06（Asia/Taipei）。状态：预览实现已完成，已通过自动化、打包和真实 Harness Web 验证；尚未发布到 npm，原生 Desktop 和付费云端实测单独保留为发布门槛。

## 目标与决定

支持 Codex、官方 DeepSeek Harness Web 和 DeepSeek Harness Desktop。分阶段完成工具调用、对话配置卡、侧栏工作台、全屏与 3D 预览。保留服务端创建配置卡后 60 秒自动提交、编辑暂停、保存立即提交、取消终止的行为；折叠、切换会话、关闭界面不取消任务。

Codex 的安装方式和 MCP 工具名称保持兼容。首版面向本机运行；远程 Harness 不会自动访问另一台机器的浏览器会话或 Blender。发布之前不自动执行付费实测，具体任务、参数及积分预算另行明确。

## 架构与接口

- 共享现有 MCP stdio 服务、登录、操作注册表、任务存储、资产、下载和 Blender 实现。
- 独立包 `tripo-studio-deepseek` 提供 `dsh.bundle`、Host 插件和 `dsh.client` 客户端。适配包固定依赖对应 Tripo 版本及经验证的 DSH 版本。
- Host 使用官方 MCP SDK 管理一个子进程。模型工具经 DSH `createMcpToolDefinition` 注册，界面共用该连接，不再重复注册 MCP Manager。
- 客户端通过 `tool.call.toolview` 注册卡片，通过侧栏标签页注册工作台；标准 MCP Apps `AppBridge` 承载现有界面。
- `/api/tripo-studio` 注册到 DSH Connection 的精确 Fetch 路由，继承宿主身份验证、取消和 Desktop 传输，不新增端口。
- 模型只收到标准 MCP 内容和公共结构化结果；完整界面结果及 `_meta` 由 Host 保存并单独投递。历史记录通过会话和调用标识恢复，不重放生成操作。
- 配置工具通过 `_meta.tripo.requires_configuration_ui` 声明界面要求。DSH 创建配置前检查对应会话已经初始化的 AppBridge；缺少界面时返回 `UI_UNAVAILABLE`，不创建任务或倒计时。
- App 使用带时效的视图令牌；卡片资源、review 和 task 操作受其绑定约束；模型和 App 工具可见性分别执行。探测视图只验证初始化，不允许调用业务工具。
- DeepSeek 界面使用不含 `allow-same-origin` 的 iframe sandbox 与限制性 CSP；OpenAI 扩展保留在 Codex 路径。

## 提交和数据兼容

计时、参数校验、重新报价、互斥提交、重启恢复与 `outcome_unknown` 对账继续归共享核心。浏览器只显示持久化状态，不另建计时或提交流程。新建前的界面就绪检查与已创建任务的后台生命周期是两件事：就绪租约过期不取消既有任务。

沿用现有账号、数据目录、资产目录与文件锁。界面展示记录保存在数据目录下 `deepseek-presentations`，不修改核心任务格式。卸载适配包不删除用户模型、任务或会话。

并行宿主验证发现并修复两处既有竞争：相同规范化输入的查重与草稿创建现在在同一个跨进程锁内执行；启动恢复先尝试取得任务的提交锁，跳过另一活进程仍在提交的任务，避免误标为中断。

## 阶段与交付

| 阶段 | 交付                                                      | 门槛                                                     |
| ---- | --------------------------------------------------------- | -------------------------------------------------------- |
| A    | 安装包、MCP 生命周期、登录/查询/报价/下载桥接             | 无界面不开放新建自动提交配置；工具撤回与子进程退出可验证 |
| B    | 对话配置卡、就绪检查、编辑/取消/等待、历史重开            | 模拟网关和真实本地操作验证，不消耗云端积分               |
| C    | 资产/任务/创建工作台、分组、图片输入、3D 预览、侧栏与全屏 | Web、Desktop 分别记录验证，Codex 回归、安装包验证通过    |

发布顺序：先发布共享运行时，再发布依赖该确切版本的 DSH 预览包。正式版本需要补齐支持平台的原生 Desktop 实测和经确认预算的云端付费闭环。源码构建、模拟测试或 Web 成功均不能替代这些记录。

## 验证要求

- 单元测试：界面就绪、会话隔离、App/模型可见性、视图过期、资源与任务绑定、历史恢复、错误与取消传递、元数据分流。
- 核心回归：60 秒到期、编辑暂停、保存提交、取消竞争、多进程锁、重启恢复、提交结果不明；使用既有可控时钟及模拟网关。
- 集成测试：真实 stdio 服务启动、62 个模型工具注册、图片导入与本地裁剪配置、取消、完整卡片结果读取、停用撤回；不调用付费云端接口。
- 打包测试：根运行时冷启动和离线缓存；适配包在隔离目录中关闭安装脚本后安装，加载内嵌资源、注册和卸载工具。
- 宿主验证：记录 DSH 版本、操作系统、Web/Desktop 类型；验证界面加载、主题、语言、窄屏、全屏及历史重开。

发布状态和已执行验证见 [DeepSeek 支持说明](DEEPSEEK.md)。
